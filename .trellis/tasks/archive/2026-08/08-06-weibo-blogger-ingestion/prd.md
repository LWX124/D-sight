# 微博账号信息获取

## Goal

在现有「社媒信息」板块中增加微博平台，使用户能够关注指定微博账号，并持续获取其发布的原创微博内容，供浏览和投研分析使用。

当前阶段先确定可持续的数据获取方式、首期产品边界与风险约束；未获得最终规划批准前不实施。

## Confirmed Facts

- 现有社媒能力只实现微信公众号；前端平台列表也只有 `wechat`。
- 微信链路采用平台专属数据表、API、抓取与定时任务，并将已抓内容暴露给 Agent 查询工具。
- 现有代码尚未实现设计文档中曾设想的通用 `SocialPlatform` 抽象；微博不能被视为只新增一个 adapter。
- 微博普通开放接口 `statuses/user_timeline` 需要 OAuth，且 `uid`/`screen_name` 只能指向当前授权用户；最多返回最新 5 条，不能用于读取任意指定博主。
- 普通开放接口按授权用户和 IP 限频；官方文档明确反对服务器机器人定时抓取，并禁止第三方服务器存储用户数据。
- 微博商业数据 API 提供按用户订阅的实时推送，官方文档称最多可指定 10,000 个用户；该能力需申请，部分收费。
- 2026-08-06 未登录实测：桌面网页能读取博主公开资料，但微博列表 Ajax 返回 HTTP 403；移动公开接口返回 HTTP 432，不能作为无需凭证的稳定数据源。
- RSSHub 的微博博主路由也调用 `m.weibo.cn/api/container/getIndex`，将该路由标记为反爬并支持 `WEIBO_COOKIES`；它属于对登录态网页接口的开源封装，不是独立、稳定或获得授权的公开数据接口。
- 第三方候选可分为三类：
  - 新浪舆情通（蜜度）公开声明有“新浪微博官方数据支持”，可做分钟级微博监测和历史回溯，但官网公开的是政企 SaaS/定制方案，未发现可直接采购的标准开发者 API 文档或价格。
  - 知微、清博、西瓜微数等分析 SaaS 提供微博传播或账号分析；公开资料不足以证明其提供可供 D-sight 落库的原始账号内容 API，需要商务确认授权来源、接口和再存储权。
  - Apify、Bright Data 等采集平台主要提供通用抓取基础设施；当前未验证到有微博官方授权的专用数据源，它们只能转移抓虫运维，不能自动消除平台条款和数据权利风险。
- 既往微博第三方 API 市场存在重大法律风险：iDataAPI 运营方因规避技术措施抓取、交易微博数据，被广东高院终审判赔 2,000 万元。因此第三方付费合同不等于微博数据授权。
- 用户确认只接受合规数据提供方：供应商必须书面证明微博授权，且合同允许 API 接入、服务器存储和向 D-sight 用户展示。
- 厂商官网未公开满足上述条件的标准 API 价格。可查的 2025 年公开采购价格主要是舆情 SaaS 账号或监控服务，不等于数据接口授权：
  - 云南省地震局采购一套新浪舆情通系统账号，成交价 20,000 元。
  - 滁州市机电工程学校采购蜜度网络舆情监控服务，成交价 18,400 元/年；采购预算上限为 28,000 元/年。
  - 其他 2025 年公开结果可见 30,000、43,000 和 70,000 元等不同服务档位；较大范围的系统平台服务公开合同可达 185,000 元。
- 历史公开采购中，包含个性化舆情数据接口能力的项目预算曾为 120,000 元；只能作为预算级参考，不能视为当前微博 API 报价。
- 用户认为商业数据或第三方授权方案价格过高；当前真实需求是低成本获取少量指定账号的公开微博内容，而非购买完整舆情监测平台。
- 用户接受首期采用 D-sight 专用微博账号登录态、低频获取少量公开账号，并将其定位为无 SLA 的实验性能力；接受验证码、登录态失效、账号限制和网页接口变更风险。
- 用户确认首期最多同时订阅 20 个微博账号。
- 用户确认首期每 60 分钟自动刷新一次。
- 用户确认首次订阅一个微博账号时只获取最新 20 条内容，之后增量更新。
- 用户确认通过粘贴微博主页链接添加账号；系统解析 UID，并展示昵称和头像供确认，不按昵称直接订阅。
- 用户确认首期只获取订阅账号发布的原创微博，过滤转发微博。
- 用户确认首期获取的微博内容必须同时供 Agent 查询。
- 用户确认首期由管理员手动配置 D-sight 专用微博账号的 Cookie；失效后提示重新配置，不开发扫码登录流程。
- 用户确认首期采用采集时快照：内容获取后保留，不持续检查后续编辑或删除；原文链接可能指向已变化或不可用的内容。

## Requirements

- 支持指定微博账号作为信息源；账号可以是个人、机构或媒体身份。
- 首期单个 D-sight 实例最多同时订阅 20 个微博账号。
- 首期每 60 分钟自动增量获取一次；不提供分钟级实时性承诺。
- 首次订阅一个微博账号时最多获取最新 20 条内容。
- 添加账号时接受微博主页链接，解析并持久化稳定 UID；确认前展示账号昵称和头像。
- 获取账号资料，以及该账号公开发布的微博内容，并能持续增量更新。
- 只保留订阅账号发布的原创微博，不采集转发微博。
- 首期微博内容至少包含正文、发布时间、原文链接和媒体链接。
- 首期不获取评论明细和粉丝画像。
- 与现有社媒板块的浏览、订阅和 Agent 使用场景保持一致。
- Agent 能按微博账号、关键词和时间范围查询已落库的微博内容。
- 微博 Cookie 只允许管理员配置，不接收普通用户的账号密码；登录态失效时提供明确状态和重新配置入口。
- 已获取的内容作为采集时快照保存，不对历史内容执行编辑、删除同步。

## Acceptance Criteria

- [ ] 管理员能配置、替换专用微博账号 Cookie；任何查询接口和日志均不泄露 Cookie。
- [ ] 用户能粘贴微博主页链接，预览昵称和头像后订阅；系统以 UID 去重，并限制全实例最多 20 个启用账号。
- [ ] 首次同步最多保存最新 20 条原创微博，之后每 60 分钟增量同步，并以微博 ID 避免重复入库。
- [ ] 用户能在社媒板块查看正文、发布时间、原文链接和媒体链接。
- [ ] Agent 能按账号、关键词和时间范围查询已获取的微博内容。
- [ ] 登录失效时凭证被标记为过期；403/432 风控时停止整轮同步并进入全局冷却；状态在微博页面可见。
- [ ] 历史快照不会因原微博后续编辑或删除而被改写。

## Out of Scope

- 首期不采购商业舆情平台或授权数据接口。
- 首期不承诺微博数据获取的可用性或实时性 SLA。
- 首期不向终端用户收集其个人微博账号密码或 Cookie。
- 首期不获取转发微博、评论明细或粉丝画像。
- 首期不开发微博扫码登录，不追踪已采集微博的编辑或删除。
- 首期不将微博内容自动写入知识库。
