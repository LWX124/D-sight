# ADR-0004: 股票诊断仅在实质冲突时复核

- **状态**: 已采纳
- **日期**: 2026-08-10
- **决策者**: lwx

## 背景

多维度的股票诊断中，不同维度可能得出矛盾结论（如估值维度看空但技术维度看多）。参考项目的做法是让所有分析角色在每次诊断中固定辩论以形成共识。

但在 D-sight 的 6 维度体系下，全量辩论有两个问题：
1. **成本**: 每次诊断调用 6 个维度 LLM + 多轮辩论，延迟和 token 消耗随维度数线性增长
2. **伪共识**: 独立维度之间不强相关，强制辩论可能产生为了"同意"而妥协的结论

## 决策

各分析维度先基于共享 `EvidencePack` 独立形成结构化意见，**仅在检测到实质冲突时**启动定向复核。风险约束由确定性规则执行，模型不能绕过。

实质冲突的判定条件（参见设计文档 5.5 节）：
1. 同一周期内同时出现高置信度多头与空头意见
2. 估值与质量维度方向相反，且任一为高置信度（`confidence >= 0.7`）
3. 技术执行条件与主周期建议相反
4. 新事件可能使既有核心论点（`thesis` 字段）失效
5. 多个维度引用同一 `evidence_id` 却得出矛盾解释

复核只接收冲突维度意见和相关证据项，不重新运行全部 6 个维度。输出必须说明：
- 冲突是否已解决
- 保留哪些异议
- 哪些证据仍缺失

## 考虑的替代方案

### 方案 A: 所有维度每次固定辩论（全量复核）

- **优点**: 最大限度的交叉验证，不会遗漏冲突
- **缺点**: 6 维度 × 多轮辩论 → 延迟不可控、成本高；相关维度少时辩论退化为主流意见的仪式性确认
- **为什么不选**: 实现复杂度与收益不成比例。在确定性风险约束已存在的前提下，多维辩论的边际收益有限

### 方案 B: 永不复核，仅展示分歧

- **优点**: 最简单，LLM 调用最少
- **缺点**: `bullish (confidence 0.8)` vs `bearish (confidence 0.8)` 的情况没有解析路径；用户面对矛盾时缺少引导
- **为什么不选**: 冲突复核的目标不是消除分歧，而是提供对分歧的解释

## 后果

### 正面
- 成本可控：仅冲突维度触发额外 LLM 调用，预计 70-80% 的诊断无需复核
- 保留分歧解释：不强制所有维度统一意见

### 负面
- 冲突检测阈值需要调优：`confidence >= 0.7` 是初始值，可能过高或过低
- 静默的置信度偏差（所有维度一致偏乐观）不会被检测到——这需要依靠后验评估（Phase 4）来发现

### 中性
- `neutral` 方向不计入冲突：这不是遗漏——中性维度不形成 actionable 意见，与 bullish/bearish 维度不在同一判定层级
